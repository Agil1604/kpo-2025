## Структура решения

### Микросервисы

Реализовано 3 микросервиса:
- [API Gateway](./API-Gateway)
- [Orders Service](./Orders-service)
- [Payments Service](./Payments-service)

Каждый микросервис представляет из себя Spring Boot приложение.
Пользователю извне доступен только API Gateway, который находится по адресу http://localhost:8080.

### Общение между микросервисами

Все входяшие API запросы перенаправляются на соответствующий им микросервис с помощью API Gateway.

Orders Service и Payments Service общаются только в случае оформления пользователем заказа.
Это происходит с помощью Apache Kafka

### Доступные API запросы

- http://localhost:8080/api/order/{userId} (Get запрос)

  Данный API запрос возвращает список всех заказов пользователя с таким userId.
  
  На вход подается только userId в пути запроса.

  Тип возвращаемого значения JSON файл состоящий из списка объектов формата
  ```Json
  {
    "id": "id заказа",
    "userId": "id пользователя оформившего заказ",
    "amount": "Сумма заказа",
    "description": "Описание заказа",
    "status": "Статус заказа"
  }
  ```
  
- http://localhost:8080/api/order/status/{orderId} (Get запрос)
  
  Данный API запрос позволяет получить статус заказа по orderId.

  На вход подается только orderId в пути запроса.

  Возвращаемое значение: Json файл с единственным полем status
  (New, если платеж еще не обработан, Cancelled, если заказ был отменен по какой-либо причине, Completed, если заказ был выполнен и все средства списаны)

- http://localhost:8080/api/order/create (Post запрос)

  Данный API запрос позволяет создать запрос на оформление заказа.

  На вход подается Json файл со следующими полями
  ```Json
  {
    "userId": "id пользователя оформившего заказ",
    "amount": "Сумма заказа",
    "description": "Описание заказа"
  }
  ```

  Возвращаемое значение: Json файл следующего формата
  ```Json
  {
    "id": "id заказа",
    "userId": "id пользователя оформившего заказ",
    "amount": "Сумма заказа",
    "description": "Описание заказа",
    "status": "Статус заказа"
  }
  ```

- http://localhost:8080/api/payment/create/{userId} (Post запрос)
  
  Данный API запрос позволяет создать аккаунт

  На вход подается userId в пути запроса и Json файл со следующими полями
  ```Json
  {
    "balance": "Баланс счета"
  }
  ```
  
  Возвращаемое значение: Json файл следующего формата
  ```Json
  {
    "id": "id пользовательского счета",
    "userId": "id пользователя оформившего заказ",
    "balance": "Баланс счета"
  }
  ```
  
- http://localhost:8080/api/payment/replenish/{userId} (Patch запрос)

  Данный API запрос позволяет пополнить пользовательский счет

  На вход подается userId в пути запроса и Json файл со следующими полями
  ```Json
  {
    "sum": "Сумма пополнения"
  }
  ```

  Возвращаемое значение: Json файл следующего формата
  ```Json
  {
    "balance": "Итоговый баланс счета"
  }
  ```
  
- http://localhost:8080/api/payment/{userId}

  Данный API запрос позволяет получить баланс счета

  На вход подается userId в пути запроса 

  Данный API запрос позволяет пополнить пользовательский счет

  На вход подается userId в пути запроса и Json файл со следующими полями
  ```Json
  {
    "sum": "Сумма пополнения"
  }
  ```
    
  Возвращаемое значение: Json файл следующего формата
  ```Json
  {
    "sum": "Итоговый баланс счета"
  }
  ```

- http://localhost:8080/api/payment/withdraw/{userId}

  Данный API запрос позволяет снять деньги со счета


  На вход подается userId в пути запроса и Json файл со следующими полями
  ```Json
  {
    "sum": "Сумма снятия"
  }
  ```
  
  Возвращаемое значение: Json файл следующего формата
  ```Json
  {
    "balance": "Итоговый баланс счета"
  }
  ```

### Сборка проекта

Сборка проекта осуществляется с помощью [docker-compose.yaml](./docker-compose.yaml), находящегося в корне проекта.
Все переменные окружения задаются в этом файле, так что при желании можно поменять под себя.

**Для сборки проекта необходимо, чтобы порт 8080 был свободен.**

При сборке создаются отдельные контейнеры для:
- каждого микросервиса
- баз данных (в нашем случае PostgreSQL) для File storing Service и File analysis Service
