# Отчет по КР2

Работа выполнена студентом группы БПИ233 Амировым Агилем. 

## Запуск

```bash
docker-compose up -d
```

Подробнее в секции "Сборка проекта"

## Структура решения

### Микросервисы

Реализовано 3 микросервиса:
- [API Gateway](./api-gateway)
- [File storing Service](./file-storing-service)
- [File analysis Service](./file-analysis-service)

Каждый микросервис представляет из себя Spring Boot приложение. 
Пользователю извне доступен только API Gateway, который находится по адресу http://localhost:8080.

### Общение между микросервисами

Микросервисы обмениваются данными между собой с помощью gRPC.
Для этого в каждом микросервисе был создан свой gRPC сервер, который оркестрируется с помощью API Gateway.


### Доступные API запросы

- http://localhost:8080/api/storage/uploadFile

  Данный API запрос загружает на сервер txt файл.

- http://localhost:8080/api/storage/{id}

  Данный API запрос получает содержимое файла по его id.    

- http://localhost:8080/api/analyze/{id}

  Данный API запрос выполняет анализ файла по его id

- http://localhost:8080/api/analyze/cloud/{id}

  Данный API запрос получает облако слов файла по его id (Важно: для этого запроса файл должен быть проанализирован)

### Документация

Так как микросервисы общаются между собой с помощью gRPC, то в документировании REST запросов нуждается только API Gateway.
Документация доступна после сборки по адресу http://localhost:8080/swagger-ui/index.html.

Там же можно выполнить тестовые запросы к серверу.

### Сборка проекта

Сборка проекта осуществляется с помощью [docker-compose.yaml](./docker-compose.yaml), находящегося в корне проекта.
Все переменные окружения задаются в этом файле, так что при желании можно поменять под себя.

**Для сборки проекта необходимо, чтобы порт 8080 был свободен.**

При сборке создаются отдельные контейнеры для:
- каждого микросервиса
- баз данных (в нашем случае PostgreSQL) для File storing Service и File analysis Service


### Архитертура

Архитектура решения соответствует требованиям чистой архитектуры. 

Все микросервисы разбиты на следующие слои:
- proto файлы (директория src/main/proto) - файлы, которые объявляют контракты для связи микросервисов.
- Директория domain - ядро приложения, которое не зависит от внешних фреймворков
- Директория infrastructure - Реализации внешних взаимодействий
- Директория application - слой приложения (в основном бизнес логика)
- Директория Presentation - Внешние интерфейсы (gRPC и REST)

Приложение обрабатывает (по крайней мере старается) все возможные ошибки.
